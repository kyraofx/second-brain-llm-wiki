# Privacy model

The public repository is a synthetic reference implementation, not a sanitized personal vault.

### Boundaries

- All people, events, projects, schedules, and experiences are fictional.
- Public examples use `sensitivity: public`.
- No personal agent memory, preferences, feelings, logs, credentials, or machine-specific paths belong here.
- Diary text is treated as immutable source material even when fictional.
- Private deployments should live in separate repositories with separate histories and access controls.

### Why separation matters

Redaction can miss information in filenames, metadata, links, attachments, Git history, or contextual combinations. Creating synthetic fixtures from the beginning provides a stronger boundary than copying and cleaning a private system.
